# Xiaomi Ares MT6893 adaptation notes

Target branch: `7.3.3-mt6893-xiaomi-ares`

This is Ares-only work. Do not copy Chopin board definitions or set MT6891 identifiers.

## WL2866D regulator inventory

Source reviewed: Xiaomi WL2866D vendor driver from Tkpointz/android_kernel_aresin (lxr), and Ares DT fragment.

| Output | Register offset | DT voltage range | Initial voltage | Step |
|---|---:|---:|---:|---:|
| DVDD1 | 0 | 600000–1800000 µV | 1050000 µV | 6000 µV |
| DVDD2 | 1 | 600000–1800000 µV | 1200000 µV | 6000 µV |
| AVDD1 | 2 | 1200000–4300000 µV | 2800000 µV | 12500 µV |
| AVDD2 | 3 | 1200000–4300000 µV | 2800000 µV | 12500 µV |

Base register: 0x03 + output offset. Enable register 0x0E; discharge register 0x02; VSET fields are byte registers. I2C address for WL2866D1 DT node: 0x28.

## Porting requirements

- Use managed I2C/regmap and regulator registration APIs in this tree.
- Register one regulator per DT child; validate offset and voltage constraints.
- Use explicit voltage mapping with range checks and reject selector values that exceed the hardware field.
- Preserve enable bits for other outputs with regmap_update_bits().
- Probe failures must propagate; do not return success on failed PID reads or failed regulator registration.
- Remove the legacy camera_ldo character device, unused ioctl, and debug sysfs controls from the initial port.
- Do not retain the vendor driver’s panel-specific first-disable workaround; panel sequencing must be handled by the panel driver and tested separately.
- Review parent-supply voting before enabling it; the reference DT supplies currently name no parent.

## Ares board references

- WL2866D1 compatible: `willsemi,wl2866d1`, I2C address 0x28.
- WL2866D2 compatible: `willsemi,wl2866d2`.
- DT fragment reviewed: `wl2866d1.dtsi`.

## Validation still required

This note is groundwork only, not a compiled or device-tested driver. The port must be compiled against the branch's regulator API, then validated on-device with rail readback, consumer mapping, display/camera power sequencing, and boot/recovery testing before being considered usable.
