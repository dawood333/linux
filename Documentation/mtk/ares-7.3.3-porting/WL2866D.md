# Xiaomi Ares MT6893 adaptation notes

Target branch: `7.3.3-mt6893-xiaomi-ares`

This is Ares-only work. Do not copy Chopin board definitions or set MT6891 identifiers.

## WL2866D regulator inventory

Reviewed references:
- Xiaomi vendor driver in `Tkpointz/android_kernel_aresin`, branch `lxr`.
- `arch/arm64/boot/dts/mediatek/ares-mt6893.dtsi` in the same reference tree.
- `wl2866d1.dtsi` is also present in that tree; its DVDD2 init-voltage differs from the board DTSI, so values must be reconciled against the actual Ares configuration before enabling rails.

| Output | Register offset | Range in reference DT | Step |
|---|---:|---:|---:|
| DVDD1 | 0 | 600000–1800000 µV | 6000 µV |
| DVDD2 | 1 | 600000–1800000 µV | 6000 µV |
| AVDD1 | 2 | 1200000–4300000 µV | 12500 µV |
| AVDD2 | 3 | 1200000–4300000 µV | 12500 µV |

**Reference init-voltage values are not fully consistent across fragments:**
- In `ares-mt6893.dtsi`: WL2866D1 DVDD1=1050000 µV, DVDD2=1260000 µV, AVDD1/2=2800000 µV. WL2866D2 DVDD1=1050000 µV, DVDD2=1200000 µV, AVDD1=2800000 µV, AVDD2=2700000 µV.
- In `wl2866d1.dtsi`: WL2866D1 DVDD2 is listed as 1200000 µV, not 1260000 µV.

The Ares board DTSI places WL2866D1 at I2C4 address 0x28 and WL2866D2 at I2C7 address 0x28. The Chopin DTS in this 7.3.3 branch instead has WL2866D1 on I2C7; that node must not be reused as an Ares wiring definition. Regulator output registers start at 0x03 plus channel offset; enable register is 0x0E and discharge register is 0x02.

## Porting requirements

- Use managed I2C/regmap and regulator registration APIs in this tree.
- Register one regulator per DT child; validate offset (0–3), exact channel-name/offset pairing, and voltage constraints.
- Use explicit voltage mapping with range checks and reject selector values that exceed the hardware field.
- Preserve enable bits for other outputs with `regmap_update_bits()`.
- Probe failures must propagate; do not return success on failed PID reads or failed regulator registration.
- Remove the legacy camera_ldo character device, unused ioctl, and debug sysfs controls from the initial port.
- Do not retain the vendor driver's panel-specific first-disable workaround; panel sequencing must be handled by the panel driver and tested separately.
- Review parent-supply voting before enabling it; reference regulator nodes do not currently define a parent supply.

## DTS integration state

The reference Ares DTS contains both WL2866D regulator nodes (I2C4/I2C7), but the 7.3.3 adaptation branch currently only has the Chopin DTS board file. The regulator driver alone is not sufficient to bring up the rails: a separate Ares board DTS and correct controller/pinctrl wiring are still required. Avoid copying the full Chopin DTS as an Ares board file.

## Validation still required

The initial driver port is not compiled or device-tested yet. Compile against the branch's regulator API, then validate on-device rail readback, consumer mappings, display/camera power sequencing, and boot/recovery before treating it as usable.
